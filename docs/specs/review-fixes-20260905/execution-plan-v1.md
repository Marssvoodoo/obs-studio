## Design and failure boundaries

- Add a small Windows SEH adapter outside C++ functions that own destructible objects, retaining the repository's normal exception compiler settings. Catch only access violations and in-page errors, not unrelated C++ exceptions, debugger traps, or stack overflow. Latch the first native fault, report it once, and avoid re-entering or unloading the damaged telemetry library. Non-Windows ordinary error behavior remains unchanged. This contains the observed call failure; it does not diagnose or repair NVIDIA's internal driver fault.
- Remove metadata as an authorization path. Load the module and initialize each candidate with the SDK's existing provider/host context, requiring the component, controller, and 32-bit audio processor supported by the runtime. Fingerprint only successful classes; rollback partial additions on failure. Increment the VST3 approval-cache schema so existing metadata-only entries require a rescan.
- Preserve out-of-process worker time/memory limits and primary-cache runtime authorization. Test fixtures use an explicitly cleared child environment, private search roots, private output caches, and bounded subprocesses.
- Reference: Microsoft's [C2712 guidance](https://learn.microsoft.com/en-us/cpp/error-messages/compiler-errors-2/compiler-error-c2712) explains separating SEH from functions requiring object unwinding. The installed VST3 SDK source is authoritative for provider lifecycle behavior.

The guarded installer must wait for OBS to be closed. After activation, VST3 effects require a fresh scan because schema-2 approvals are intentionally rejected.
